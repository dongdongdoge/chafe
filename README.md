# Chafe Shuffle Evaluation Artifact

This artifact contains the code, data, validation checks, and third-party
backend source used to reproduce the Chafe Shuffle evaluation.  The repository
is organized so that every reported value is regenerated from code and every CSV
row records its provenance through a `source_type` field.

## Artifact Claims

- Formula-derived privacy and utility-factor curves are generated from the
  closed-form expressions in the paper.
- The Drop validation figure is generated by an exact finite-domain
  hockey-stick accountant for a small BRR instance.
- The ingestion figures use a measured Google
  `distributed_point_functions` write-backend benchmark.
- Workload figures are Monte Carlo simulations with at least 30 seeds.
- The real-data workload uses a cleaned copy of the UCI Adult/Census Income
  dataset included under `datasets/adult/`.

## Repository Layout

- `experiments/`: experiment drivers, accountants, simulators, figure generator,
  validation checks, and the Google DPF build wrapper.
- `data/`: CSV files for all figures and validation summaries.
- `figures/`: generated TikZ/PGFPlots output directory.  Generated `.tex`
  figures are ignored by Git and can be recreated from the scripts.
- `datasets/adult/`: cleaned Adult workload input and dataset metadata.
- `third_party/distributed_point_functions/`: vendored Google DPF source used
  by the ingestion microbenchmark.

## Environment

Python 3.9 or newer with NumPy is sufficient for the Python experiments:

```bash
python -m pip install -r requirements.txt
```

The measured DPF benchmark requires Bazel and a C++ toolchain.  On the macOS
environment used for the reported measurements, the wrapper script applies
explicit include flags to avoid mixing Homebrew OpenSSL headers with BoringSSL.
On a clean Linux or macOS toolchain, a shorter Bazel invocation may be
sufficient.

## Reproduction

Build the Google DPF benchmark:

```bash
python experiments/build_google_dpf.py
```

Regenerate the full artifact:

```bash
python experiments/run_all.py
```

This command regenerates:

- `data/*.csv`
- `figures/*.tex` in the working tree
- `data/validation_summary.txt`

It also prints the main numerical takeaways.  The checked-in
`datasets/adult/adult_clean.csv` is used by default, so a normal rerun does not
require network access.  To re-download and clean the Adult dataset from the
official UCI source, run:

```bash
python experiments/fetch_adult_dataset.py
```

## Validation

Run:

```bash
python experiments/validate_results.py
```

The validation checks include:

- Drop privacy decreases with load factor `rho`.
- Drop privacy decreases with release expansion `tau`.
- IdealShuffle privacy is independent of `rho` and `tau`.
- Collision-regime fractions sum to one.
- Exact-accountant and proxy Drop values remain in the same broad order.
- Google DPF product and dual-track reconstructions agree.
- Microbenchmark rows have positive measured time.
- All Monte Carlo figures use at least 20 seeds.
- All figure CSVs contain only the expected `source_type` values.

## Provenance Labels

Each CSV row uses one of the following `source_type` values:

- `formula`: closed-form or second-order expression from the paper analysis.
- `exact_accountant`: exact finite-domain hockey-stick accounting.
- `microbenchmark`: measured wall-clock benchmark.
- `monte_carlo`: workload-level simulation.
- `analytic_cost`: analytic cost model, not a measurement.

These labels should be used when describing results in the paper.  Values marked
`formula` are not exact accountant outputs, and values marked `analytic_cost`
are not measured runtime.

## Notes

The Google DPF measurement is a backend microbenchmark, not an end-to-end
deployment throughput claim.  In the current backend, product-valued writes have
lower normalized expansion work and smaller keys, but are not faster in
wall-clock time than the dual-track benchmark.  Privacy and workload utility are
decoupled from this concrete DPF backend.
